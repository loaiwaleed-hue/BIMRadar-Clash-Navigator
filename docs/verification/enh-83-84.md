# Verification: #83 clash colours by item order, #84 zoom, overlap, selection

Scope: this covers the maths (a Python mock) and a code read. **Revit writes are untested**: category/element overrides, `ZoomAndCenterRectangle` and `Selection.SetElementIds` need the owner's Revit 2022 test on a model copy. Nothing was compiled here (no .NET or nuget access).

## API check (Revit 2022-2027)
- `View.SetCategoryOverrides(ElementId, OverrideGraphicSettings)`: exists since 2014, so in 2022-2027.
- `UIView.ZoomAndCenterRectangle(XYZ, XYZ)`, `UIView.GetWindowRectangle()` (System.Drawing.Rectangle), `UIDocument.GetOpenUIViews()`, `View.RightDirection` / `UpDirection`: all in 2022-2027.
- `Compat.LinkToHostView` (reflection, missing on 2022) is removed, with its call.

## #83 design
- Item order: `Hit.Item` is set in `FindHits` from the position in `VpCam.Items` (1 = first, 2 = second).
- Host hit: per-element override in item colour (1 red 255,0,0; 2 green 0,170,0), solid surface/cut patterns and line colours.
- Linked hit: category override on the host category (matched by BuiltInCategory id, else by name, as in #81).
- Overridden element ids and category ids are tracked per view; both are reset with a default `OverrideGraphicSettings` before the next clash and on Clear override.
- Two linked items in one category: item 1 wins, and a note goes into the window info.
- Applied in the VP view and the WIP view, after `ApplyCategories`.

## #84 design
- `HitsBox` is the union of `HitBox` (link transform applied). It is grown 15% plus 0.3 m per side, projected on RightDirection/UpDirection, widened on the covered side, then turned back into two XYZ corners at the box centre depth.
- Clash only (not Revizto or viewpoint items). VP view only.
- Selection is cleared after a clash navigation (VP and WIP). The ID buttons use the "Pick" action, which returns before this code and still selects.

## Mock of the overlap extension
View 1600 px wide, form covering 380 px on the left, box 2 m wide on the right axis (10..12).

```python
def extend(rmin, rmax, view_w, cover_px, left, cap=0.6):
    f = min(cover_px / float(view_w), cap)
    add = (rmax - rmin) * f / (1.0 - f)
    if left: rmin -= add
    else: rmax += add
    return f, add, rmin, rmax

f, add, a, b = extend(10.0, 12.0, 1600, 380, True)
print(f, add, a, b)
visible = 1600 - 380
print((11.0 - a) / (b - a) * 1600 - 380, visible / 2.0)   # box centre vs visible-part centre
print(extend(10.0, 12.0, 1600, 1200, False))               # 75% covered: capped at 0.6
```

Output:

```
f=0.2375 add=0.6230 new=[9.3770, 12.0000] width=2.6230
box centre 610.0 px from the left edge of the visible part (visible part 1220 px, centre 610.0)
(0.6, 3.0, 10.0, 15.0)    # cap
```

The box centre lands in the middle of the visible 1220 px, and the box fills the visible part's width before the 15% + 0.3 m margin.
