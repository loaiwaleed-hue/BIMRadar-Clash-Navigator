# Verification: #77, #78, #79, #80

Method: code read only. Nothing here was compiled or run (no .NET / Revit in the sandbox). It covers READS of the code paths and API names; every Revit WRITE (view settings, category visibility, element overrides, view names) is untested and must be proven by the owner on a model copy.

## #77 Fine detail, annotations hidden except the section box
- `ShadedMedium` renamed `ShadedFine`, now `ViewDetailLevel.Fine` (exists 2022-2027). Called for the VP view and the work view.
- New `HideAnnotationsExceptSectionBox(View v)`: skips views with a view template; for each `Category` of `doc.Settings.Categories` with `CategoryType.Annotation`, not OST_SectionBox, `CanCategoryBeHidden(cat.Id)` true and not hidden yet -> `SetCategoryHidden(cat.Id, true)`; try/catch per category; finally OST_SectionBox is made visible. The inline loop in `DuplicateOrtho` (C5 behaviour) was replaced by a call to this method, so the code exists once. The VP view calls it in the main "Clash Viewer" transaction.
- API: `View.CanCategoryBeHidden(ElementId)`, `View.SetCategoryHidden(ElementId, bool)`, `View.GetCategoryHidden(ElementId)`, `Category.CategoryType`: all present in the already-used code (ApplyCategories) and in Revit 2022-2027 docs (to be re-checked by the owner on revitapidocs).
- Not verified: that Section Boxes is classed as Annotation on every version (the old inline code assumed it too), and the visible result.

## #78 Work view name
- Prefix is now `WIP-Clash Viewer-` + VP view name; uniqueness loop ("(2)", "(3)") unchanged.

## #79 Another-model warning
- `NavHandler.OtherIdx` (VpCam.Index -> bool) is filled in `Execute` from `IsOtherModel(c, doc)` each time an item is navigated (same call as the old `NotHere`, now evaluated once). The form reads only the cache, never the Revit document.
- `NavForm.ShowWhy`: Revizto and cached true -> `lblWhy3` red: "Anchored to another model: {c.Model} - the view may be empty or wrong here." (em dash; falls back to the model list if c.Model is empty). Takes precedence over the grey summary and the empty-view text. Navigation unchanged.
- Limit: an item never visited has no cache entry, so no line until it is opened.

## #80 Clash colours
- Handler: `ColorsOn` (default true); `colored` map view id -> overridden ids; `Colorize(doc, view, isClash, hits)` clears the previous overrides in that view (`SetElementOverrides(id, new OverrideGraphicSettings())`), then for clash items with ColorsOn paints host hits red (255,0,0) and the `RevitLinkInstance` of linked hits green (0,170,0). Whole method and each element are in try/catch: failures never break navigation.
- Called after `ApplyIsolation` (section box already set) in the VP-view transaction and in the work-view transaction.
- Solid fill: `FillPatternElement.GetFillPatternElementByName(doc, FillPatternTarget.Drafting, "<Solid fill>")`, fallback scan of `FillPatternElement` with `GetFillPattern().IsSolidFill` and Drafting target (covers localised Revit). If none is found, only line colours are set.
- API: `OverrideGraphicSettings.SetSurfaceForegroundPatternId/Color`, `SetCutForegroundPatternId/Color`, `SetProjectionLineColor`, `SetCutLineColor`, `View.SetElementOverrides`. All exist 2022-2027 (foreground pattern API since 2019.1); the obsolete ProjectionFill* members are not used. Nothing version-specific, so Compat.cs is unchanged.
- Action `ToggleColors`: flips `ColorsOn`, then clears / re-applies in the active view when it is a VP- or WIP-Clash Viewer- 3D view, else the VP view, in its own transaction "Clash Viewer - clash colours". Applies to the current item's `Hits`.
- Form: button `btnColor`, clash source only, text "Clear override" when ColorsOn else "Create override" (`SyncColors`, called from `Sync`). Position: same row as "Duplicate 3D view", right part (Left 248, width 120); Duplicate is 232 wide in clash layout. The Go to element button (Revizto only) never shares a clash window.
- Untested risks for the owner: (1) overrides set while the view is in temporary hide/isolate mode (done after `IsolateElementsTemporary`); if Revit refuses, the colours are silently absent. (2) Link override colours the whole link instance, as intended. (3) Cut patterns only show where the section box cuts.
- Owner test list: clash item -> element red, link green; Next clash -> previous element back to normal; Clear override -> colours off, button reads Create override; Create override -> back; Duplicate 3D view -> work view coloured when on, plain when off; Revit 2022 and one newer version.
