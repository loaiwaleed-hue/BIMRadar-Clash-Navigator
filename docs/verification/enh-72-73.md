# Verification: #72 (empty 3D view) and #73 (locate by coordinates)

Scope: Revizto items only. Nothing is ever written to Revizto data. Code is marked `// #72` / `// #73`.

## What changed
- `Navigator/LocationCheck.cs` (new, static, read-only, no transactions):
  - `CountModelElementsInBox`: `BoundingBoxIntersectsFilter(Outline)`, counts only elements with a Category of `CategoryType.Model`, not `ViewSpecific`, not `RevitLinkInstance`; stops at 1000.
  - `ModelsNear`: host (`doc.Title`) plus each loaded link; the host box's 8 corners go through `GetTotalTransform().Inverse` and the AABB is counted in the link document. A failing link is skipped.
  - `ElementOffset`: metres from `c.Point` to the centre of the nearest found hit's box (`NavHandler.HitBox`, which already applies the link transform; now `internal`).
  - `Summary` and `PickHint` (hint priority a, b, c, d as in the ticket).
- `Navigator/NavHandler.cs`: `LocResult`, `Loc`, `EmptyIdx`, `OffsetLimit` (max(Box size, 2 m)); `ReviztoBox(c)` extracted from Execute with unchanged numbers; `ComputeLoc`; Execute computes the result after `tx.Commit` for Revizto items; new actions `CheckAll` (no view change) and `GotoElement` (like Refresh, section box and camera around the first found element via `ClashBox`, no result recompute).
- `Navigator/NavForm.cs`: "Hide empty" checkbox and "Check locations" button (new row under the Filter row, Revizto only); "Go to element" button right of "Duplicate 3D view" (Duplicate shrinks to 232 px while it shows); `lblWhy3` (red "Nothing from this model at this location" or the grey summary) and a yellow `lblHint` under `lblWhy2`; Revizto client height 1080 and picture reserve 122 px (others unchanged); `RefreshLoc` re-applies Hide empty (the item just opened stays in the list) and redraws.
- Not done (per the design): the result cache is per session, not stored in `navigator_status.json`. Clash and viewpoint sources are unchanged.
