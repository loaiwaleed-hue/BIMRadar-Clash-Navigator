Method: code read only. Not compiled and not run in Revit (no .NET / Revit in the sandbox). Covers reads of the code paths; the Revit writes (view isolation, view creation) are unchanged by these tickets and still need the owner's Revit test on a model copy.

## #93 Isolate button
- `NavForm.cs`: `noIso = !isClash`, so `btnIso.Visible` is true only for the clash source. The only other places that touch `btnIso` are the Enabled/Text/BackColor block in `Sync`, now guarded by `if (isClash)` (the old non-clash else branch was removed), the click handler and the tooltip.
- Layout: for Revizto and viewpoints `btnSnap` already uses Left 12, Width 356 when `noIso`, so there is no gap.
- `NavHandler.cs`: the #69 guard (`Isolate` on a Revizto source sets Isolated = false) is untouched, and `ApplyIsolation` is still called with `Isolated && !Source.StartsWith("Revizto")`.

## #92 Remember source / Change source
- `NavigatorEntry.cs`: static `LastByDoc` (key = `doc.PathName`, else `doc.Title`) with `LastSource{Kind, Path}`, persisted to `last_by_doc.txt` in the settings folder (`key|kind|path`, newest last, trimmed to 50, loaded lazily once).
- `Open(uiapp, forceDialog)`: if not forced and the remembered file/folder exists, the dialog is skipped; otherwise the existing dialog flow runs. Both routes call one `LoadSource(kind, path)` method (the old load code, moved, not duplicated). `Open(uiapp)` still works.
- `Remember` runs in `LoadSource` after the load succeeded (all failure returns come earlier). Viewpoints store the project folder.
- The old window is closed after the source is chosen, so cancelling the dialog from Change source leaves it open.
- `NavForm.cs`: button `btnChange` "Change source" with a left-pointing triangle, top right on the title row (Left 268, Top 10, 100x26). The title label was narrowed from 356 to 252 px so they do not overlap. Previous / Next and everything below are unchanged. Click sets `H.ChangingSource` and `H.Action = "ChangeSource"` and raises the ExternalEvent.
- `NavHandler.cs`: action `ChangeSource` calls `Launcher.Open(app, true)`, the same path the ribbon uses, now with a `forceDialog` overload. The form is closed from inside its own event, so `FormClosed` disposes the ExternalEvent on the next `Application.Idle` when `ChangingSource` is set.
