# Verification: #81, #82

Method: code read only. Nothing was compiled or run (no .NET / Revit / nuget in the sandbox). It covers READS of the code paths and API names. Every Revit WRITE (category visibility, link display, element overrides, temporary isolate) is untested and must be proven by the owner on a model copy.

## Why the linked element could be invisible (#81)
1. Category hidden by host id. `ApplyCategories` hid every model category whose host-document id was not in the "keep" set, and the keep set was built from `cat.Id.ToString()` of the element in the link document. For built-in categories the id is the same in both documents, but only by luck of the string form; for any other category (project-defined, or a category the link has and the host lacks) the id is different or absent, so the linked element's category was hidden in the host view and the link showed nothing. If the category could not be read for one hit, the others still hid it.
2. Link display override. The view can show a link "By linked view" or "Custom". Then the host view's category hiding does not drive the link, and element overrides set on the link instance (the green) are not applied. The tool never looked at this.
3. Not found hits: nothing was isolated and nothing said so (FindHits only set `Where`; the window showed the same line either way), so the box looked like "everything".
4. The green is one override on the whole link instance (Revit has no per-linked-element override), so the remaining isolated linked elements are green only when 1 and 2 are fine.

## What changed (#81)
- `Compat.IdValue(ElementId)`: reflection, property `Value` (2024+) else `IntegerValue` (2022/2023). `IntegerValue` is only a string, never called.
- `ApplyCategories(doc, view, HashSet<long> keepIds, HashSet<string> keepNames)`: keeps a category when its id value is in keepIds (BuiltInCategory match, link id == host id for built-ins) or its name is in keepNames (fallback). OST_RvtLinks and OST_SectionBox are always kept. `keepIds == null` shows all model categories (unisolated or no linked hit).
- `CatOf` now returns the top-level `Category` of the element in its own document; `ApplyIsolation` adds both id value and name for every found hit. If one found hit has no readable category, nothing is hidden (visibility of the element wins over tidiness).
- Link display: `Compat.LinkToHostView(view, linkId)`. `View.GetLinkOverrides/SetLinkOverrides` and `RevitLinkGraphicsSettings.LinkVisibilityType` (enum ByHostView) are, to my knowledge, in the API since Revit 2019, but I could NOT check revitapidocs here (no network). So they are reached by reflection: if a member is missing in a version, the call returns a note and nothing breaks at compile time or run time. When the link is not By host view it is set to By host view in this tool's own VP / work view (before the green is applied); the previous setting is reported in the window ("<link>: link display was ByLinkView, set to By host view in this view"). The ticket said both "leave it but log it" and "set it if safe": I chose set + log, because left as is the green and the category hiding cannot work. A view with a view template can refuse; the error is shown as a note, never thrown.
- Hit rows (`NavForm.ShowHits`): Found = old text + " · <category>" (`Hit.CatName`, filled in `FindHits`); not found = red "<n>. <model> #id: NOT FOUND (<Where>)".
- No hit found at all (clash): red line "Clash elements not found in this model or its links: the view shows everything in the box." (`ShowSelection(found, total, clash, linkNote)`). It replaces the old grey text for clashes. The link note is prepended to the info line otherwise.
- Green: `Paint` already sets surface + cut foreground pattern (Drafting `<Solid fill>`) and colour, projection + cut line colour (0,170,0 for links). Order is now explicit and commented: link display -> `ApplyCategories` (inside `ApplyIsolation`) -> `Colorize`, in both the VP view and the work view. No change to Paint's settings.

## #82 Isolate / Unisolate for clash
- `NavigatorEntry`: `h.Isolated = true` when the source is the Navisworks clash test (default isolated at load).
- Decision in both places (VP view, work view) is now `Isolated && !Revizto`; the `|| c.IsClash` is gone. The existing action `Isolate` toggles `Isolated` and runs the normal refresh.
- Unisolated: `ApplyIsolation(on:false)` runs `DisableTemporaryViewMode(TemporaryHideIsolate)` and shows all model categories again (the categories hidden by the isolated state have to be restored, else "unisolate" would leave them hidden). Section box code and `Colorize` run as before, so box and colours stay.
- Form: `noIso = isVp || isRevizto`, so the button shows for clash. Label "Unisolate" when isolated, "Isolate" when not (amber when isolated); enabled once a clash has been opened. Position: same row as "Save solved snapshot", split width (button 12..188, snapshot 192..368), the existing non-clash layout. Revizto and VP unchanged.
- The "Duplicate" message only says "clashing elements isolated" when Isolated.

## API used
`Element.Category`, `Category.Parent / Name / Id / CategoryType`, `View.CanCategoryBeHidden / GetCategoryHidden / SetCategoryHidden`, `View.IsolateElementsTemporary / DisableTemporaryViewMode / IsInTemporaryViewMode`, `OverrideGraphicSettings` setters (unchanged), `BuiltInCategory.OST_RvtLinks / OST_SectionBox`. Version-specific members: only `ElementId.Value / IntegerValue` and `View.Get/SetLinkOverrides`, both via reflection in Compat.cs.
